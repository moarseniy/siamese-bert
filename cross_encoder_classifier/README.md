# Cross-encoder: коды и тональность

Парный Transformer для русскоязычных ответов из опросов. Для каждой конечной
подкатегории модель получает пару:

```text
[CLS] текст ответа [SEP] код. текстовое описание кода [SEP]
```

и предсказывает один из четырех классов:

| Класс модели | Значение |
|---:|---|
| 0 | код отсутствует |
| 1 | код присутствует, тональность нейтральная (`0` в разметке) |
| 2 | код присутствует, тональность позитивная (`1` в разметке) |
| 3 | код присутствует, тональность негативная (`2` в разметке) |

На инференсе один ответ проверяется против всех конечных подкатегорий. Пары,
которые модель считает отсутствующими, отбрасываются; остальные коды и их
тональности собираются в мультилейбл-результат.

## Установка

```bash
cd cross_encoder_classifier
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Данные

Предпочтительный формат обучающего CSV/XLSX:

| Ответ | Коды_новые | Тональности |
|---|---|---|
| Зарплата низкая, но коллектив отличный. | A1, B1 | 2, 1 |
| Обычное рабочее место. | A2 | 0 |
| Ничего не могу сказать. | UNKNOWN | |

Порядок тональностей должен совпадать с порядком кодов. Значения исходной
тональности: `0` нейтральная, `1` позитивная, `2` негативная. Вместо отдельной
колонки можно записывать `A1:2, B1:1` прямо в колонке кодов.

Текущая четырёхклассовая модель поддерживает одну тональность на код. Ответы,
где один код размечен несколькими разными тональностями, например
`I4:1, I4:2`, автоматически исключаются до разбиения на `train/val/test`.
Точные повторы одной пары, например `I4:1, I4:1`, просто дедуплицируются.
Количество исключённых ответов и номера исходных строк печатаются перед
обучением и сохраняются в `data_report.json`.

Справочник хранится в CSV с обязательными колонками `Код`, `Категория`,
`Подкатегория`:

```csv
Код,Категория,Подкатегория
A1,Условия труда,Уровень заработной платы. Размер оклада и соответствие рынку.
A2,Условия труда,Рабочее место. Оборудование и комфорт.
B1,Команда,Коллектив. Атмосфера и отношения между сотрудниками.
```

Каждая строка уже является конечной подкатегорией. Отдельные строки `A`, `B`
не нужны. В парный вход модели включаются и категория, и подкатегория. Описание
должно быть содержательным: от него напрямую зависит перенос на новые или
измененные коды.

## Обучение

```bash
python scripts/train.py \
  --train ../data/train.xlsx \
  --codebook ../data/codes.csv \
  --out-dir model_out \
  --base-model /path/to/rubert-base-cased \
  --text-col "Ответ" \
  --codes-col "Коды_новые" \
  --sentiments-col "Тональности" \
  --context-col "Вопрос" \
  --val-size 0.1 \
  --test-size 0.1 \
  --seed 42 \
  --epochs 3 \
  --batch-size 16
```

`--base-model` принимает как локальную папку Hugging Face-модели, так и ее id.
По умолчанию используется `DeepPavlov/rubert-base-cased`.

Разбиение на `train/val/test` выполняется до создания пар, поэтому один и тот
же ответ не попадает в разные части. Все положительные пары сохраняются. В
`train` по умолчанию берется по три случайных отсутствующих кода на каждый
положительный (`--negative-ratio 3`), чтобы класс `0` не задавил остальные.
До половины доступной квоты сначала заполняется сложными негативами из той же
основной категории, затем добавляются случайные. Случайность фиксируется через
`--seed 42`. Для обучения на всех отрицательных парах добавьте `--all-negatives`.
На `val` и `test` всегда проверяются все конечные коды независимо от этой
настройки.

Основные артефакты в `model_out/`:

- `model/` и `classifier_config.json`;
- `data_report.json` с количеством загруженных и исключённых строк;
- `splits/` с исходными ответами, разделенными до генерации пар;
- `pair_distribution.csv` с балансом четырех классов;
- `val_metrics.json`, `test_metrics.json`, `metrics.json`;
- `*_per_class.csv`, `*_pair_per_class.csv`, `*_predictions.csv`, `*_errors.csv`.

## Инференс

С сохраненным при обучении справочником:

```bash
python scripts/predict.py \
  --input ../data/answers.xlsx \
  --output predictions.xlsx \
  --model-dir model_out \
  --text-col "Ответ" \
  --context-col "Вопрос" \
  --batch-size 64 \
  --max-labels 6
```

Для расчета метрик по размеченному файлу:

```bash
python scripts/predict.py \
  --input ../data/test.xlsx \
  --output test_predictions.xlsx \
  --model-dir model_out \
  --gold-codes-col "Коды_новые" \
  --gold-sentiments-col "Тональности"
```

Если gold-разметка содержит несколько тональностей одного кода, предсказание
для такой строки всё равно сохраняется, но строка исключается из метрик. Число
исключений записывается в `skipped_conflicting_sentiment_rows` внутри
`*_stats.json` и выводится в консоль.

Главные выходные колонки: `predicted_codes`, `predicted_sentiments` с
позиционно совпадающими значениями и самодостаточная
`predicted_code_sentiments` вида `A1:2, B1:1`.

## Измененный справочник

Новый CSV можно передать только на инференсе:

```bash
python scripts/predict.py \
  --input ../data/answers.xlsx \
  --output predictions_new_codes.xlsx \
  --model-dir model_out \
  --codebook ../data/codes_v2.csv
```

Голова модели не привязана к конкретным id кодов, поэтому она может оценивать
новые описания. Это дает zero-shot-перенос, но не гарантирует прежнее качество:
небольшие уточнения справочника обычно переносятся лучше, чем совершенно новые
темы или новое понимание тональности. Такой перенос стоит отдельно измерять на
размеченной выборке нового справочника.

## Метрики

На верхнем уровне находятся основные прикладные метрики по собранным ответам:
`micro_precision`, `micro_recall`, `micro_f1`, `macro_f1`,
`subset_accuracy`, `hamming_loss`, `unknown_prediction_rate` и
`gold_code_sentiment_accuracy`. Метрики `joint_micro_f1` и `joint_macro_f1`
считают совместную метку «код + тональность»; `gold_code_sentiment_accuracy`
считает верной только пару, где нужный код найден и его тональность совпала.

Секция `pair` показывает диагностику исходной четырехклассовой задачи по всем
парам: `accuracy`, `macro_f1`, `presence_precision/recall/f1` и точность
тональности на истинно присутствующих парах. При выборе модели по умолчанию
используется `joint_micro_f1`, поскольку обычная pair accuracy может
выглядеть высокой из-за большого числа отсутствующих кодов.
